# CLAUDE.md

Публичный репозиторий конспектов книг (Бёрнс «Терапия настроения», Кларк-Бек, Маккей, Бек, Восс «Никаких компромиссов»). Ведёт заметки Лела; читает книги по главам.

Репозиторий ПУБЛИЧНЫЙ. Сюда идут только конспекты книг. Личное — разборы, моя история, мои ситуации, ссылки на мои файлы, имя моего терапевта — сюда не писать никогда: оно живёт в приватном репозитории `DavidBurnsFeelingGood` (соседняя папка). Если в конспект просится личная связь, вынести её туда, в `Практика/Личное-из-конспектов.md`. Полные тексты книг тоже не публикуются: они лежат в приватном репозитории в папке `Источники/`.

## Обращение

Лела — женщина. Обращаться в женском роде (женские формы глаголов, причастий, прилагательных). Отвечать по-русски, кратко и по делу.

## Структура заметок

- `README.md` — индекс: таблица прогресса по главам со ссылками и статусом («в работе» / «готово»).
- Одна папка на книгу: `Burns-Feeling-Good/`, `Clark-Beck/`, `McKay-ACT/`, `Beck-Cognitive-Therapy-of-Depression/`, `Voss-Never-Split-the-Difference/`; сопоставления книг между собой — в `Comparisons/`.
- `<Папка-книги>/Chapter-NN_Title.md` — один файл на главу. Подглавы книги оформляются разделами `##` внутри файла; не дробить главу на отдельные файлы. Индекс книги, если нужен, — `00_About-the-Book.md`.
- При добавлении новой главы — завести файл и строку в таблице `README.md`.

## Имена папок и файлов — только по-английски

Natural Reader не открывает ссылки, в пути которых есть кириллица. Поэтому все имена папок и файлов в репозитории (включая картинки и новые подпапки) пишутся по-английски:

- Переводом на английский, а не транслитом: `Chapter-06_Verbal-Judo.md`, а не `Glava-06_Verbalnoe-dzyudo.md`.
- Если у главы есть устоявшееся английское название из оригинала книги и оно совпадает по смыслу с русским, брать его; иначе переводить русское название. Номер главы — по русскому изданию.
- Слова через дефис, номер главы двузначный: `Chapter-NN_Title.md`; рисунки — `Fig-N.M_Title.svg`.
- Содержимое файлов (заголовки, текст, подписи ссылок) остаётся на русском — правило касается только путей.
- При переименовании — `git mv` (чтобы сохранялась история) и сразу обновлять все ссылки на файл: `README.md`, индексы `00_…`, перекрёстные ссылки между заметками, этот `CLAUDE.md`.
- Держать статус главы в `README.md` актуальным: ставить «готово» по завершении полного конспекта главы и «разобрано частично», когда сознательно законспектированы только отдельные разделы или таблицы. Обновлять статус сразу, как закончили работу над главой.

## Порядок работы: сначала глава, потом сквозные заметки

Заметка по главе — первичная и самодостаточная. Пишется так, как будто сквозных заметок не существует: ничего не выносится наружу, ничего не заменяется ссылкой, читается без обращения к другим файлам.

Строгая последовательность:

1. Написать заметку по главе. Не смотреть в `Burns-Feeling-Good/00_Recurring-Techniques-and-Tables.md` и другие сквозные файлы, не искать пересечений, не ставить на них ссылок.
2. Спросить Лелу и получить подтверждение, что заметка принята, закоммитить и запушить.
3. Только после этого открывать сквозные заметки и искать пересечения. По итогам либо дописать краткую строку в `00` со ссылкой на главу, либо не делать ничего.

Сквозные заметки вторичны: в них только краткое упоминание приёма и ссылка вниз, на главу, где он разобран подробно. Разворачивать материал в сквозной заметке вместо главы нельзя.

### Цитируемое ≠ утверждаемое автором

Различать, что Бёрнс утверждает сам, а что приводит, чтобы оспорить. При сжатии текста опровержение теряется первым, и чужая гипотеза начинает читаться как позиция автора — это считается фактической ошибкой конспекта. Сохранять маркер отношения автора: «считалось», «по мнению X», «убедительных доказательств нет», «это крайность и мышление „всё или ничего“».

Примеры из главы 7: гипотеза Фрейда о направленном внутрь гневе как причине депрессии (Бёрнс приводит её и отмечает, что доказательств нет); цитаты Уэйна Дайера о том, что справедливости не существует, а гнев бесполезен (приведены как пример мышления «всё или ничего» и сверхобобщения).

### Термин «называние аффекта»

Приём Восса label / labeling в конспектах называть «называнием аффекта» (назвать аффект, называние эмоции), а не «навешиванием ярлыка», как в русском переводе. «Ярлык» и «навешивание ярлыка» оставлять только в смысле Бёрнса — когнитивного искажения. В дословных цитатах из перевода заменять слово в квадратных скобках: «[Называние аффекта] – это…».

### Только то, что работает

Конспект — не пересказ, а то, что автор по итогу рекомендует делать. Подходы, методы и советы, от которых автор отказался или которые он опровергает (чужие школы, «принято считать», устаревшие сценарии, неудачные приёмы из разборов провалов), в конспект не переносить вовсе — ни списком, ни пересказом. Из провалов оставлять только вывод-правило. Пример: четыре принципа «Пути к согласию» у Восса в конспект главы 1 не входят.

## Стиль конспекта

Этот раздел действует ТОЛЬКО для заметок по главам книг, то есть для файлов в папках `Burns-Feeling-Good/`, `Clark-Beck/`, `McKay-ACT/` и `Voss-Never-Split-the-Difference/`. Ко всему остальному — `README.md`, `Comparisons/` и прочим рабочим файлам — правила краткости и сжатия не применяются: там пишем настолько подробно, насколько нужно для дела, с объяснениями «зачем», примерами и повторами, если они помогают.

Кратко и структурировано: списки определений, нумерованные перечни (искажения, предположения, виды требований «должен»). Форматирование маркирует структуру, а не эмоцию — без выделения слов ради акцента.

Не терять задания. Книга нужна не для чтения, а для практики, поэтому в заметке должно быть видно, где Бёрнс даёт задание читателю. Такие места переносить как задание («записать», «считать две недели», «репетировать с другом», «перечитывать каждое утро»), а не как эпизод из чужой терапии. Типичная потеря: упражнение изложено через историю пациента — «Арт записал мысли в две колонки», «Джош вёл листок», — а адресованная читателю инструкция рядом с ним исчезает. Сохранять и режим: сколько раз в день, сколько недель, с кем.

Не терять списки исходника: если у Бёрнса перечисление (шаги приёма, пункты памятки, признаки, ожидания), в конспекте оно тоже должно быть списком, а не свёрнутым в одну фразу пересказом.

Объём: заметка — выжимка, а не пересказ. Правила против распухания:

- Один смысл излагается один раз. Если мысль уже сформулирована в разделе про искажения, в разделе про приёмы её не повторять — ссылаться.
- Примеры и кейсы сжимать, но не до потери логики: из кейса должно быть понятно, кто участники и в каких они отношениях, что на кону, почему стороны ведут себя именно так (скрытый мотив, рычаг, страх), что конкретно сделали и чем кончилось. Лучше на 2–3 предложения длиннее, чем непонятно. Сюжет по шагам не пересказывать. Диалоги и ролевые игры не воспроизводить — только их итог.
- Дословно цитировать лишь то, что теряет смысл в пересказе (формулировки правил, критерии, определения). Всё остальное — своими словами и короче исходника.
- Проверка после написания: можно ли выкинуть слово, фразу или абзац без потери смысла? Если да — выкинуть.

Исключение: таблицы переносятся дословно, они распознаны из книги и правке не подлежат.

Оформление диалогов: реплики оформлять цитатой (`>`), каждую с новой строки, реплику начинать с тире. Чтобы строки не склеивались в один абзац, в конце каждой реплики, кроме последней, ставить два пробела — это жёсткий перенос. Пустые строки цитаты (`>`) между репликами не использовать, они раздувают блок. Образец — `Burns-Feeling-Good/Chapter-06_Verbal-Judo.md`.

Оформление таблиц: у каждой таблицы должно быть название-заголовок (`#### Таблица N.M — название` для нумерованных в книге; `#### Таблица: название` для сведённых мной). Перед таблицей — упоминание её в тексте в контексте мысли/приёма (для книжных — по номеру, напр. «(табл. 13.2)»; для сведённых — по названию, напр. «см. таблицу ниже»), затем отдельно сама таблица с заголовком. Образец — `Burns-Feeling-Good/Chapter-08_Guilt.md`.

## PDF для прослушивания

PDF из заметок для чтения вслух (Natural Reader) собирается только скиллом `/tts-pdf`. Скилл — единственный источник правды по генерации таких PDF: формат страницы, вёрстка, подготовка текста к синтезу речи, разбор жалоб на озвучку. Здесь эти правила не дублируются; если они расходятся со скиллом, прав скилл.

Если по ходу работы появляется идея, как улучшить чтение PDF (что-то читается криво, сливается, не произносится), не править это разово в заметке или в одном PDF и не записывать правило сюда. Вместо этого напомнить Леле, что надо поправить скилл, и прислать готовый текст правки для `skill-creator`.

## Git

- Ветка `master`. Ветку не переключать без явной просьбы.
- Коммитить и пушить только по явной команде.
- Но о незакоммиченных изменениях напоминать самой: закончив правку, в конце ответа коротко сообщать, что осталось незапушенным, и предлагать пуш. Молчать про накопившиеся изменения нельзя.
- Стиль сообщений: `docs: ...` — заметки; `chore: ...` — служебное.
- Desktop Commander использовать ТОЛЬКО для git-операций (коммит/пуш): `start_process` + локальный git на машине пользователя. Для чтения/правки файлов его не применять.
- Токен из `.gittoken` больше не нужен (файл удалён): у локального git своя аутентификация, пуш идёт через `origin` обычным `git push`.
- Сообщение коммита с кириллицей передавать через файл (`git commit -F <файл>` в UTF-8), а не `-m` (PowerShell искажает кодировку аргумента).
